What you are driving#

The arm has two links of length 1, joined at an elbow, with its base at the origin. Its whole configuration is two joint angles, q1q_1q1​ at the base and q2q_2q2​ at the elbow, measured in radians. Where the hand ends up is fixed by those two numbers:

x=cos⁡q1+cos⁡(q1+q2),y=sin⁡q1+sin⁡(q1+q2).x = \cos q_1 + \cos(q_1 + q_2), \qquad y = \sin q_1 + \sin(q_1 + q_2).x=cosq1​+cos(q1​+q2​),y=sinq1​+sin(q1​+q2​).

That map from joint angles to hand position is the arm's forward kinematics. It is the reason driving by hand feels awkward. Turning the base joint swings the whole arm along a circle; turning the elbow bends only the outer link, so the hand moves along a smaller circle centred on the elbow. Neither control moves the hand in a straight line, and the direction each one pushes changes as the arm moves.

An action is a change to the two joint angles. Each step clips it to at most 0.20.20.2 rad per joint, so a long reach takes many steps. The hand has reached a block when its centre is within 0.150.150.15 of the block's centre.

The arm starts at q=(π/2,−π/2)q = (\pi/2, -\pi/2)q=(π/2,−π/2): upper link straight up, lower link pointing right, hand at (1,1)(1, 1)(1,1). The three blocks, red, green and blue, are placed by a seed, always within reach and clear of the arm's starting pose. The same seed always gives the same table.

The check#

The check replays your recorded moves from the same seed, one step at a time, and passes if the hand ever reaches the block you named. It uses the world's own step, so a drive that worked on screen works here.

Check source
import json
import os

from world.blockworld import BLOCKS, REACH, Blockworld
from world.check import expect

PATH = "artifacts/teleop.json"
expect(
    os.path.exists(PATH),
    "No recorded drive yet. Drive the hand onto the block you named, and the drive is saved.",
    file=PATH,
)
with open(PATH) as f:
    episode = json.load(f)
expect(
    isinstance(episode, dict) and {"seed", "target", "actions"} <= set(episode),
    "The recording needs a seed, a target and a list of actions.",
    file=PATH,
)
expect(episode["target"] in BLOCKS, f"The target must be one of {', '.join(BLOCKS)}.", file=PATH)

world = Blockworld(seed=episode["seed"], target=episode["target"])
closest = world.distance()
reached = False
for action in episode["actions"]:
    _, _, done, info = world.step(action)
    closest = min(closest, info["distance"])
    reached = reached or done
expect(
    reached,
    f"Replaying {len(episode['actions'])} moves never brings the hand within {REACH} "
    f"of the {episode['target']} block; the closest it gets is {closest:.2f}.",
    file=PATH,
)
print(f"Reached the {episode['target']} block in {len(episode['actions'])} moves.")

The world from Python#

The widget draws what Python sends it and computes nothing itself; world/blockworld.py is the only physics. You can drive the same world from code. show(world) sends the current frame to the widget, and summary() is the text version of what it shows.

A scripted drive is a loop of step calls. This one turns only the base joint, which swings the hand around a circle of radius 2\sqrt{2}2​ about the base, since the elbow stays bent at a right angle. The blue block sits at radius 1.501.501.50, close enough to that circle that the hand passes within reach of it, and then keeps going: reaching a block does not stop the arm.

Key takeaways#

  • The arm is two numbers, the joint angles. The hand position follows from them through forward kinematics, and that map is not linear.
  • Driving by hand is hard because each joint pushes the hand in a direction that changes as the arm moves. Every later rung replaces you with something that learns that relationship.
  • The world is deterministic under a seed, and the widget holds no physics of its own, so what you see and what the checks measure never disagree.
