Autograd from scratch

Write the Tensor every later rung trains with, then let its gradients steer the arm.

Loading Python

On rung 0 you steered the arm yourself, guessing which joint to turn from how the picture looked. This rung replaces the guessing with a derivative, and builds the machinery that computes derivatives for everything after it.

The failure#

Nothing here can learn yet: there are no gradients. To move the hand toward a block on its own, the arm needs to know how the distance to the block changes when each joint turns a little. That is ∂d/∂q1\partial d / \partial q_1∂d/∂q1​ and ∂d/∂q2\partial d / \partial q_2∂d/∂q2​. You could work those out by hand for this one formula, but every network on every later rung is a different formula with thousands of parameters. You need a program that differentiates whatever you compute.

Goal: the arm reaches the red block on its own, steered by gradients your Tensor computes.

One primitive, many operations#

Reverse-mode automatic differentiation records each operation as it runs, then walks the record backwards applying the chain rule. Your Tensor wraps a NumPy array and remembers the operation that produced it.

The whole design rests on one method, Tensor.op(forward, backward, *parents):

  • forward(*arrays) takes the parents' arrays and returns the output array.
  • backward(grad, *arrays) takes the gradient of the final result with respect to this output, plus the parents' arrays, and returns a tuple with one gradient per parent.

With op written, every other operation is a line or two. Multiplication is Tensor.op(np.multiply, lambda g, a, b: (g * b, g * a), self, other), because the derivative of ababab with respect to aaa is bbb. Later rungs add softmax and convolution the same way, in their own files, so keep that signature exactly.

Three things are easy to get wrong, and the check tests each one.

A value used twice gets both contributions. In y=x⋅x+xy = x \cdot x + xy=x⋅x+x, the value xxx feeds three edges, and dy/dx=2x+1dy/dx = 2x + 1dy/dx=2x+1 is the sum over all of them. The multivariate chain rule says the gradient at a node is the sum, over every path to the output, of the gradient along that path. So backward must accumulate into .grad, never overwrite it, and must visit a node only after everything that uses it has passed its gradient back. That order is a reverse topological sort of the graph.

Broadcasting has to be undone. Adding a bias of shape (3,) to a batch of shape (4, 3) copies the bias into four rows. Each copy contributes to the result, so the bias gradient is the upstream gradient summed over those four rows. In general, sum over the leading axes the parent did not have, and over every axis where the parent had size 1. Do this once, inside backward, for every gradient op returns.

Matrix products transpose. For C=ABC = ABC=AB with upstream gradient Cˉ\bar CCˉ, the gradients are Aˉ=CˉB⊤\bar A = \bar C B^\topAˉ=CˉB⊤ and Bˉ=A⊤Cˉ\bar B = A^\top \bar CBˉ=A⊤Cˉ. Check the shapes: with AAA of shape (n,k)(n, k)(n,k) and BBB of shape (k,m)(k, m)(k,m), Cˉ\bar CCˉ is (n,m)(n, m)(n,m), so CˉB⊤\bar C B^\topCˉB⊤ is (n,k)(n, k)(n,k), matching AAA. Use np.swapaxes(x, -1, -2) rather than .T so the same code handles a batch of matrices times one matrix, which rung 9 needs.

The check#

The check compares your gradients with numerical ones. For each input entry it nudges the value by ±10−6\pm 10^{-6}±10−6 and measures the change in the output, the central difference (f(x+h)−f(x−h))/2h(f(x + h) - f(x - h)) / 2h(f(x+h)−f(x−h))/2h, which is accurate to order h2h^2h2. It does that for every operation alone, for broadcasting in both directions, for a reused node, and for a small network. Then it adds sin through Tensor.op, the way later rungs will add operations, and checks that too.

Check source
import numpy as np

from world.check import expect, require

FILE = "mine/autograd.py"
Tensor = require("mine.autograd", "Tensor").Tensor
rng = np.random.default_rng(0)


def numeric_grad(f, arrays, i, h=1e-6):
    x = arrays[i]
    grad = np.zeros_like(x)
    for idx in np.ndindex(x.shape):
        old = x[idx]
        x[idx] = old + h
        hi = f(*arrays)
        x[idx] = old - h
        lo = f(*arrays)
        x[idx] = old
        grad[idx] = (hi - lo) / (2 * h)
    return grad


def gradcheck(name, build, *shapes, positive=False):
    arrays = [rng.normal(size=s) for s in shapes]
    if positive:
        arrays = [np.abs(a) + 0.5 for a in arrays]
    tensors = [Tensor(a.copy()) for a in arrays]
    out = build(*tensors)
    expect(isinstance(out, Tensor), f"{name}: expected a Tensor, got {type(out).__name__}", file=FILE)
    expect(out.shape == (), f"{name}: .sum() should give a scalar, got shape {out.shape}", file=FILE)
    out.backward()
    value = lambda *xs: float(build(*[Tensor(x) for x in xs]).data)
    for i, t in enumerate(tensors):
        want = numeric_grad(value, arrays, i)
        expect(t.grad is not None, f"{name}: input {i + 1} got no gradient", file=FILE)
        got = np.asarray(t.grad)
        expect(got.shape == want.shape, f"{name}: gradient of input {i + 1} has shape {got.shape}, expected {want.shape}", file=FILE)
        err = float(np.max(np.abs(got - want)))
        expect(np.allclose(got, want, rtol=1e-4, atol=1e-6), f"{name}: gradient of input {i + 1} is off by up to {err:.3g}", file=FILE)

def sin(t):
    return Tensor.op(np.sin, lambda g, a: (g * np.cos(a),), t)

Drive the arm with your gradients#

Now use it. The distance from hand to block is a function of the two joint angles, so its gradient says which way to turn each joint. sin and cos are not in your core Tensor, so add them here the way later rungs add operations: one Tensor.op each.

scratchRuns in this rung's shared namespace

Each pass builds the hand position from the current angles, measures the squared distance to the block, and takes a gradient step on the joints. The world clips each step to 0.20.20.2 rad, so far from the block the arm moves at full speed whatever the step size. Near the block the step size is what matters: change 0.1 to 0.5 and the hand overshoots, then bounces between two poses 0.170.170.17 and 0.200.200.20 from the block, never landing inside the 0.150.150.15 reach.

Try target="green" or another seed. Gradient descent finds a nearby way to reach the block, not necessarily the elbow configuration you would have chosen by hand. The squared distance has more than one minimum in joint space, one per elbow configuration, and the descent settles into whichever basin it starts in.

Key takeaways#

  • Reverse mode needs each operation's local derivative and an order: visit every node after everything that uses it, and add, never overwrite, the gradients that arrive.
  • Broadcasting in the forward pass becomes a sum in the backward pass. Handling it once, inside op, keeps every operation simple.
  • Tensor.op is the extension point. Every later rung that needs a new operation adds it the way this page added sin, without editing this file.
  • The arm reached the block by descending a loss built from its own kinematics. The next rung removes the assumption that you know those kinematics.
