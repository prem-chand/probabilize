Observations: state and pixels

Decide what a policy sees of the world, as an exact state vector or as a small camera image, and teach a network to find a block in the pixels.

Loading Python

Every scratch cell so far read the block positions straight out of the simulator, world.blocks["red"], and the arm's angles out of world.joints(). A policy on a real robot gets no such dictionary. It gets what its sensors report, and deciding what that is comes before any policy can be trained.

The failure#

A policy has nothing to read. Rung 2's network knows where the hand is from the joint angles, but nothing in the workspace describes the table, the blocks or the target in a form a network can take as input. And the one source the simulator makes easy, exact block coordinates, is the one a real robot does not have.

Goal: two observation functions for every later rung to share, and a network that looks at a 16×1616 \times 1616×16 camera image and says where the red block is.

Two observations#

A state observation is a short vector of exactly the quantities the task depends on. It is cheap and noiseless, and in simulation it is free. Here it has thirteen numbers:

  • cos⁡q1,sin⁡q1,cos⁡q2,sin⁡q2\cos q_1, \sin q_1, \cos q_2, \sin q_2cosq1​,sinq1​,cosq2​,sinq2​, the joint angles without the wrap-around seam rung 2 removed;
  • the red, green and blue block positions, xxx then yyy for each;
  • a one-hot vector over red, green, blue marking the target.

A pixel observation is what a camera sees. world.rgb(16) renders the table as a 16×1616 \times 1616×16 image with three colour channels. Each pixel covers 0.25×0.250.25 \times 0.250.25×0.25 of the table, and a block, 0.50.50.5 wide, covers about four pixels. A network reading this image has 768 numbers in front of it and has to work out for itself which few of them matter. Scale the image to [0,1][0, 1][0,1] as float32: networks train on small floats, and the whole Build uses 32-bit observations to halve memory once datasets grow.

Both functions must leave the world untouched. An observation that stepped or reset the world would change what it was observing, and a policy would act on a world it had already disturbed.

The check#

The check pins the layout, dtype and values of the state vector, and checks the image's shape, dtype, range and determinism: the same world must give the same pixels, and a different table must give different ones. Then it trains an MLP from your mine/nn.py, with your Adam, to read the red block's position from 384 camera images, and tests it on 128 tables it has not seen.

Check source
import numpy as np

from world.blockworld import BLOCKS, Blockworld
from world.check import expect, require

FILE = "mine/obs.py"
obs = require("mine.obs", "state_obs", "pixel_obs")
nn = require("mine.nn", "MLP", "Adam")
Tensor = require("mine.autograd", "Tensor").Tensor

world = Blockworld(seed=3, target="green")
world.step([0.1, -0.2])
before = world.state().copy()

s = obs.state_obs(world)
expect(isinstance(s, np.ndarray), f"state_obs should return a NumPy array, got {type(s).__name__}", file=FILE)
expect(s.shape == (13,), f"state_obs should have shape (13,), got {s.shape}", file=FILE)
expect(s.dtype == np.float32, f"state_obs should be float32, got {s.dtype}", file=FILE)
q = world.joints()
want = np.concatenate(
    [[np.cos(q[0]), np.sin(q[0]), np.cos(q[1]), np.sin(q[1])], *(world.blocks[b] for b in BLOCKS), [0.0, 1.0, 0.0]]
).astype(np.float32)
wrong = np.flatnonzero(~np.isclose(s, want, atol=1e-5))
expect(not wrong.size, f"state_obs differs from the documented layout at index {wrong[:1].tolist()}: got {s[wrong[:1]]}, expected {want[wrong[:1]]}", file=FILE)

p = obs.pixel_obs(world)
expect(isinstance(p, np.ndarray) and p.shape == (16, 16, 3), f"pixel_obs should have shape (16, 16, 3), got {getattr(p, 'shape', type(p).__name__)}", file=FILE)
expect(p.dtype == np.float32, f"pixel_obs should be float32, got {p.dtype}", file=FILE)
expect(p.min() >= 0.0 and p.max() <= 1.0, f"pixel_obs should lie in [0, 1], got {p.min():.3f} to {p.max():.3f}", file=FILE)
expect(np.allclose(p, world.rgb(16) / 255.0, atol=1e-6), "pixel_obs should be world.rgb(16) scaled to [0, 1]", file=FILE)
expect(np.array_equal(obs.pixel_obs(world), p), "pixel_obs should give the same image twice for the same world", file=FILE)
expect(not np.array_equal(obs.pixel_obs(Blockworld(seed=4)), p), "pixel_obs gave the same image for two different tables", file=FILE)
expect(np.array_equal(world.state(), before), "an observation changed the world; observations must only read it", file=FILE)


def dataset(seeds):
    images, red = [], []
    for seed in seeds:
        w = Blockworld(seed=seed)
        images.append(obs.pixel_obs(w).reshape(-1))
        red.append(w.blocks["red"])
    return np.array(images), np.array(red)


x_train, y_train = dataset(range(1000, 1384))
x_test, y_test = dataset(range(5000, 5128))
rng = np.random.default_rng(1)
model = nn.MLP([768, 32, 2], activation="relu", seed=0)
optimizer = nn.Adam(model.parameters(), lr=0.01)
for _ in range(300):
    batch = rng.integers(0, len(x_train), 64)
    loss = ((model(Tensor(x_train[batch])) - Tensor(y_train[batch])) ** 2).sum(axis=1).mean()
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

error = float(np.linalg.norm(model(Tensor(x_test)).data - y_test, axis=1).mean())
guess = float(np.linalg.norm(y_test - y_train.mean(axis=0), axis=1).mean())
expect(
    error < 0.35,
    f"from pixels, the network's held-out error on the red block is {error:.3f}; it needs to be under 0.35 "
    f"(always guessing the average position scores {guess:.3f}).",
    file=FILE,
)
print(f"Red block from pixels: held-out error {error:.3f}, against {guess:.3f} for guessing the average.")

The error on new tables is larger than on the training tables. The network gave each of the 768 inputs its own weights, so what it learned about a block at one spot on the table says nothing about a block one pixel over; it has to see blocks in every spot. That is the price of ignoring the structure of an image, and rung 8 pays it back with an encoder that shares weights across patches.

Key takeaways#

  • An observation is a design choice. The state vector is exact and short but exists only in simulation; pixels are what a robot has, and they make the network find the few numbers that matter.
  • Observations read the world and never change it, and they are deterministic, so a policy's input depends only on the state it is in.
  • A plain MLP can read a block's position from pixels, but it learns every pixel position separately, and its held-out error shows it.
